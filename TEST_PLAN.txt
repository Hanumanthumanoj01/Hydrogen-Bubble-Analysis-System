TEST PLAN — from installation to the finished PDF
==================================================

Work through the steps in order. The last check, check_results.py, compares
every number of the report with your own outputs automatically, so you do not
have to compare numbers by hand. Send its output file back; if it says
"0 failed   0 skipped", the report and your data agree.

All folder names are relative to the project folder, the one that holds
backend/ and frontend/ (for example ~/Downloads/hydrogen-bubble-analysis).


----------------------------------------------------------------------
STEP 1   INSTALL
----------------------------------------------------------------------
Unzip code_bundle.zip INTO the project folder so that its backend/ and
frontend/ merge with yours (replace files when asked). Your own simulator.py,
package.json, CameraAnalyzer.jsx, export.js and index.css are not in the
bundle and stay as they are. The Image tab (ImageAnalyzer.jsx) is unchanged.
backend/run_session_D.py and backend/make_session_D.py from earlier
bundles are replaced by make_sessions.py; you may delete them.
NEW IN v10/v11: the "Every bubble, froth included" detector of Tab 1 was
rewritten (report Sections 3.5 and 3.15.7), and both detectors now ignore
the timestamp text, black borders and player bar of a screen capture.
Step 4a has new expected values and Step 4e checks a screen capture.
v11 also adds the cloud deployment files (Dockerfile, .dockerignore,
render.yaml, backend/requirements.txt; see DEPLOY_GUIDE.pdf), lowers the
memory of the Video tab, and refines the wording rules of make_sessions.py.
Copy Dockerfile, .dockerignore and render.yaml into the project folder.

    cd ~/Downloads/hydrogen-bubble-analysis
    pip3 install opencv-python numpy scipy scikit-image pandas matplotlib \
                 openpyxl fastapi uvicorn python-multipart scikit-learn joblib
    python3 verify_install.py

EXPECT  sections 1-6 PASS, section 7 "skip" (server not started yet).

----------------------------------------------------------------------
STEP 2   PUT THE DATA IN PLACE  (one command does the checking)
----------------------------------------------------------------------
This is where every file has to be. The names on the left are what the
scripts look for, all inside backend/:

  backend/
    session_A/     Session A, the 12 AVI files 020mA_01.avi ... 500mA_01.avi
    session_B/     Session B, the 16 AVI files 20260713_bigbubbles_...avi
                   (ONLY the AVI files, no MP4 copies in here)
    session_C/     Session C, the 5 AVI files bubble_video_...avi
    Session_D/     Session D, the 10 recordings at 50 ... 500 mA/cm2
    Session_E/     Session E, all its recordings (3D electrode and mesh)
    Session_F/     Session F, all its recordings (also the copies of Session D
                   recordings it contains: they are recognised and counted once)
    videos/        5 copies: the 100, 300, 600 and 900 mA MP4 files
                   and the 100 mA AVI (20260713_bigbubbles_...)
    screenshots/   the two screen captures (211925_..._860mA, 212403_..._721mA),
                   bubble_density_600mA_02.jpg, and later your 5 app screenshots
    results_A/ results_B/ results_C/ results_screenshots/   (already computed)

  Sessions D, E and F are analysed in Sections 4.14 to 4.16, and Section
  4.17 compares all six sessions.

You do not have to arrange this by hand. In the project folder:

    python3 check_layout.py           shows what is where, changes nothing
    python3 check_layout.py --fix     puts things in place
    python3 check_layout.py           again: should say "Everything is in
                                      place" apart from the screenshots of Step 4

What --fix does: a session folder spelt differently ("Session A",
"session-a", ...) gets a link under the expected name, your folder stays as
it is; a required file found elsewhere in the project, in ~/Downloads or on
the Desktop is COPIED to where it is needed; an MP4 copy lying in session_B/
is MOVED to videos/. Nothing is deleted. Every action is printed.

A file listed as [MISS] is not on the computer in any of these places:
copy it in from wherever you keep the laboratory data and run the check again.

The screen captures may keep the names macOS gave them, with spaces; both
spellings are accepted.

Send layout_report.txt (written by the check) together with the results of
Step 7.
