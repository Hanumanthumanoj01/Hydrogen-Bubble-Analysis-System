# Bubble detector — YOLO training pipeline

## What's actually here (verified working in this sandbox)

- `generate_pseudo_labels.py` — runs the classical detector (the same
  `bubble_analysis.py` used by the FastAPI backend) over a folder of images
  and writes YOLO-format bounding-box labels. **Tested**: generated 324
  labels across the 3 real `bubble_density_*.jpg` images, matching the
  counts the backend API itself reports (118/110/96).
- `data.yaml`, `train_yolo.py` — dataset config + training script.
  **Tested**: ran a 1-epoch smoke test (`yolov8n.yaml`, no pretrained
  weights, 320px, batch 2) — model built, data loaded, forward/backward
  pass executed, checkpoint written to
  `runs/detect/smoke_test/weights/best.pt`. This proves the *mechanics*
  of the pipeline are correct.

## What this is NOT

The smoke-test run produced Precision/Recall/mAP = 0. That is the correct,
expected result — not a bug — because:

1. **No pretrained weights.** This sandbox's network whitelist doesn't
   include `release-assets.githubusercontent.com`, which is where
   `ultralytics` actually redirects to when downloading `yolov8n.pt`. I
   could not download it here. Training was initialized from a random
   architecture (`yolov8n.yaml`) purely to prove the code runs — a real
   run needs to start from the pretrained checkpoint.
2. **3 images is not a dataset.** `train` and `val` currently point at the
   *same* 3 files. There is no held-out validation, and no model can learn
   general "bubble-ness" from 3 examples regardless of epochs.
3. **The labels are pseudo-labels**, generated by the classical detector
   itself. A model trained only on these learns to imitate the classical
   detector's own blind spots — it cannot exceed it. They're a fast
   *starting point* for correction, not ground truth.

## What you actually need to do to get a real model

1. **Get `yolov8n.pt` onto whatever machine trains this** — either train
   somewhere with normal internet access (your own machine, or Google
   Colab's free GPU tier, Runtime → Change runtime type → GPU), where
   `ultralytics` will download it automatically, or download it yourself
   from https://github.com/ultralytics/assets/releases and place it in
   this folder.
2. **Get real images.** Capture ~300-500 frames across your actual
   electrode types and current densities (100/200/600 mA/cm² and beyond) —
   the more varied the lighting/density, the better it generalizes.
3. **Correct the pseudo-labels, don't create from scratch.** Run
   `generate_pseudo_labels.py` on your new images, then open the images +
   `.txt` files in CVAT, Roboflow, or Label Studio and fix them — add
   missed bubbles, delete false positives, adjust boxes. This is the step
   that actually teaches the model something the classical detector
   doesn't already know; it typically cuts labeling time by a lot compared
   to drawing every box from nothing.
4. **Train for real:**
   ```
   python train_yolo.py --data data.yaml --epochs 100 --imgsz 640 --batch 16
   ```
   On a free Colab GPU this is a coffee-break job, not a multi-day one.
5. **Wire `best.pt` into `bubble_analysis.py`** in place of (or alongside,
   for comparison) the Hough pipeline — happy to write that integration
   once you have real trained weights.

## Honest expectation-setting

The other AI's accuracy table (Hough 60-80%, YOLO-seg 95-99%) is a
reasonable *ceiling* comparison in the literature, not a guarantee — actual
performance depends entirely on label quality and quantity. Don't expect
99% from 300 quickly-corrected pseudo-labels; expect a genuine, measurable
improvement over Hough, worth the labeling effort, but not a magic number.
